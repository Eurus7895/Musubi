Mental model đầu tiên: The driver reasons. Musubi controls the environment. Model tạo reasoning, text và tool request; driver sở hữu model call, goal state và orchestration; substrate kiểm soát deterministic action, context, validation, persistence và evidence mà không gọi model.

Trục 1 — trust boundary

Model-calling driver gọi model qua LMRouter; zero-LLM governance substrate gate và ghi evidence; read-only operator projection chỉ đọc trạng thái an toàn; operator control là mutation/authoring do người dùng chủ động như Setup và Pipeline Studio; external system nằm ngoài quyền kiểm soát của Musubi.

Trục 2 — lifecycle

Durable investment là primitive đáng duy trì; ephemeral compensation phải có removal trigger. Trục này độc lập với trust: worker loop là durable driver, không phải zero-LLM substrate. musubi-tier chỉ là metadata triển khai riêng.

Thuật ngữ: surface là cửa vào của operator; worker là một vòng run_unit; pipeline là recipe nhiều stage xác định; skill là capability/prompt được inject hoặc tải; audit evidence là record bền; fail-closed nghĩa là không có allowlist thì deny; substrate là governance không gọi LLM; ephemeral là scaffolding có ngày hết hạn.

Unified worker model chỉ có nghĩa root và child dùng chung primitive run_unit. Root giữ goal state, phase routing, recovery và quyền đọc rộng hơn; child nhận brief đóng băng, pushed skill và tool/spawn bị giới hạn.

Bản tóm tắt tĩnh của 13 kịch bản

  1. Direct request → one worker. Root giữ GoalState, chọn một bounded worker; worker mới là nơi mutation xảy ra.
  2. Root-selected pushed skill. Root chọn role; substrate inject role skill vào frozen brief trước LM call của worker.
  3. Same-turn siblings. Nhiều tool uses được phát trong cùng model turn chạy concurrent; kết quả trở lại theo thứ tự tool use.
  4. Nested helper. Worker được phép summon helper trong depth cap; spawn và completion đều có audit.
  5. Explicit deterministic pipeline. Operator chọn --pipeline; primary stages chạy sequential theo recipe, không do model tự route.
  6. Declared stage helpers. Một primary stage có thể fan out helpers khi pipeline.yaml khai báo spawns:; backbone stages vẫn sequential.
  7. Policy denial. Unknown hoặc disallowed role/tool bị deny trước execution.
  8. Evaluator firewall. Reviewer yêu cầu request, plan hay memory bị chặn; chỉ artifact cần judge được lộ.
  9. Budget stop. Cycle, output hoặc total-run ceiling dừng worker với terminal evidence thay vì chi tiêu tiếp.
  10. Reversible context fitting. Replay data được nén hoặc elide, còn original dispatch được bảo toàn.
  11. Safe Console projection. Rust đọc state/audit DB và React render evidence; không có LM call.
  12. Viewed versus active session. Console có thể xem session cũ trong khi shared driver process thuộc session khác; viewing không chuyển ownership.
  13. External MCP isolation. Connection failure được log và skip; namespaced call đi tới owning server, ngoài Musubi-owned policy/audit boundary.

Static summary of 13 scenarios

  1. Direct worker: root routing preserves goal authority while a bounded worker owns mutation.
  2. Pushed skill: role contracts are revalidated and injected before the child model call.
  3. Same-turn siblings: one response creates a concurrent batch whose results retain tool-use order.
  4. Nested helper: bounded depth and explicit audit prevent silent delegation.
  5. Deterministic pipeline: the operator chooses the recipe and primary stages remain sequential.
  6. Declared helpers: a stage may fan out only roles declared in spawns:.
  7. Policy denial: missing authority is denied before execution.
  8. Evaluator firewall: the evaluator sees only the artifact being judged.
  9. Budget stop: executable ceilings end work before another model call.
  10. Context fitting: elision preserves a recoverable reference to original dispatch.
  11. Console projection: database reads and rendering are zero-LLM.
  12. Viewed versus active: viewing history never transfers driver ownership.
  13. External MCP: namespaced calls route outside the Musubi-owned policy and audit boundary.

Bất biến và chuỗi nhân quả

Phân loại failure: model failure là kết quả reasoning kém; driver failure là orchestration/context/recovery sai; substrate denial là boundary cố ý chặn; substrate defect là chính boundary vi phạm contract.

HI #1 — zero LLM calls in substrate

Risk: governance tự reasoning và không còn deterministic. Assumption: driver là layer duy nhất cần model. Enforcement: model access qua LMRouter; server, validation, policy và audit không import SDK. Evidence: router usage và zero-LLM substrate source boundary. Violation: gọi OpenAI từ policy engine. Bỏ enforcement sẽ biến allow/deny thành nondeterministic và phá control boundary.

HI #2 — push skills, pull on demand

Risk: worker thiếu role contract hoặc tự bỏ qua skill. Assumption: root/composer biết role trước worker. Enforcement: spawn context trả role_skill, system prompt nhúng nó; agent chỉ pull skill phụ qua musubi_get_skill. Evidence: frozen spawn prompt. Violation: gửi chỉ skill ID tùy chọn. Bỏ push path làm direct worker và pipeline stage có contract khác nhau.

HI #3 — evaluator firewall

Risk: judge bị bias bởi intent, plan, design hoặc memory. Assumption: evaluator chỉ cần artifact nó judge. Enforcement: reviewer stage permissions chỉ cho code; final-stage brief chỉ mang output ngay trước. Evidence: denied read và last-stage brief. Violation: reviewer đọc plan. Bỏ một trong hai gate tạo leakage qua MCP hoặc runner.

HI #5 — fail-closed policy

Risk: unknown authority nhận tool hoặc stage execution. Assumption: chỉ membership và allowlist rõ ràng mới hợp lệ. Enforcement: catalog validation khi boot, membership re-check khi spawn, role/pipeline tool intersection. Evidence: policy verdict và denied tool event. Violation: unknown reviewer được shell. Bỏ deny default biến lỗi config thành authority escalation.

HI #7 — append-only stage store

Risk: retry xóa provenance của attempt trước. Assumption: maintainer cần toàn bộ chuỗi evidence. Enforcement: retry ghi <stage>.attemptN.md, read path chọn attempt rõ ràng. Evidence: immutable attempt artifacts. Violation: overwrite code.md. Bỏ suffix attempt làm review và recovery không thể tái dựng.

HI #8 — no silent sub-agents

Risk: fan-out không có accountability. Assumption: mỗi child có parentage và terminal outcome. Enforcement: spawn và completion append rows vào subagent_audit. Evidence: queryable handle, parent, role, status. Violation: helper chạy mà không có row. Bỏ completion write tạo orphan không phân biệt running với lost.

HI #9 — tag and expire

Risk: ephemeral scaffolding trở thành permanent accidental architecture. Assumption: model capability tăng sẽ làm một số compensation hết cần. Enforcement: card phản ánh musubi-tier khi source header khai báo; source tier ephemeral mang đúng expires-when và cost-lever của file. Evidence: source metadata và PR review. Violation: thêm prompt scaffold không expiry. Bỏ metadata làm dissolution không có trigger.

Failure classes are distinct: model failure is poor reasoning, driver failure is incorrect orchestration or recovery, substrate denial is an intentional boundary, and substrate defect is a broken contract.

HI #1 — zero LLM calls in substrate

Risk: governance becomes nondeterministic. Enforcement: only driver-side LMRouter reaches models; server, validation, policy, and audit import no model SDK. Violation: a policy path calls a provider.

HI #2 — push skills, pull on demand

Risk: a worker misses or ignores its role contract. Enforcement: spawn context returns role_skill and the child system prompt embeds it; optional skills remain pull-based.

HI #3 — evaluator firewall

Risk: intent, plan, design, or memory biases evaluation. Enforcement: reviewer permissions expose only code and the final-stage brief carries only the immediately preceding artifact.

HI #5 — fail-closed policy

Risk: unknown authority receives tools or stage execution. Enforcement: boot-time catalog validation, spawn membership checks, and explicit role/pipeline tool intersections deny missing authority.

HI #7 — append-only stage store

Risk: retry overwrites earlier provenance. Enforcement: every retry creates a distinct attempt artifact such as <stage>.attemptN.md.

HI #8 — no silent sub-agents

Risk: fan-out loses accountability. Enforcement: every spawn and completion appends queryable parentage, role, handle, and terminal outcome.

HI #9 — tag and expire

Risk: temporary scaffolding becomes permanent architecture. Enforcement: ephemeral source declares expires-when and cost-lever metadata reviewed with its evidence.

Tiến hóa và dissolution

Mỗi record theo chuỗi previous shape → observed problem → design decision → current shape → future removal trigger. Historical interpretation: các chuyển tiếp dưới đây giải thích lịch sử; current runtime cards phía trên vẫn là evidence cho hiện trạng.

  1. Fixed pipelines: fixed four-stage pipeline → khó tái dùng topology → tách preset và recipe → user-defined worker recipes → bỏ scaffolding khi model có thể tự thỏa contract an toàn.
  2. Unified execution primitive: main/sub-agent distinction → duplicated loops và semantics → hợp nhất execution → root, child và stage dùng run_unit với authority khác nhau → xóa compatibility wrappers khi caller cũ biến mất.
  3. VS Code removal: embedded VS Code host → ownership và model access bị chia đôi → giữ một standalone host → standalone CLI plus native Console → xóa extension residue khi schema/comment compatibility hết cần.
  4. Builder-only Studio: Pipeline Studio execution surface → chat/session ownership trùng Orchestrator → tách authoring khỏi execution → builder-only workspace và explicit Orchestrator launch → xóa legacy read fields khi migration window đóng.
  5. GoalState: accumulated root transcripts → context phình và recovery mập mờ → giữ exact intent cùng bounded feedback → current-run GoalState và OutcomePacket → thu nhỏ scaffold khi provider reasoning đủ tin cậy.
  6. Pushed skills: skill-only reachability gap → worker có thể không pull role contract → root chọn và spawn path inject → pushed role skill plus on-demand pull → gộp metadata khi tool protocol mang contract native.
  7. Token-only accounting: unbounded or duplicated limits → nhiều owner và credit semantics không quy vế → mỗi dimension một executable owner → provider/estimated token-only accounting → xóa compatibility fields sau khi reader cũ hết hạn.
  8. Thinner prompts: fixed prompt scaffolding → ephemeral compensation tích tụ → tag expiry và cost lever → frozen brief nhỏ hơn và pushed skills → delete khi model capability đáp ứng failure threshold.
  9. Catalog relocation: platform-neutral catalogs under .github/ → storage path ngụ ý platform ownership → lên kế hoạch relocation → catalog vẫn ở .github/ trong current repo → move khi compatibility readers và migration được ship.

Each transition reads as previous shape → observed problem → design decision → current shape → future removal trigger. These records explain history; the runtime cards remain the evidence for current behavior.

  1. Fixed pipelines: a rigid four-stage topology became reusable presets plus user-defined worker recipes, with scaffolding removed when models satisfy the safety contract natively.
  2. Unified execution: duplicated main/sub-agent loops converged on run_unit while authority remains specific to depth and role.
  3. VS Code removal: split ownership moved to one standalone host with a native Console.
  4. Builder-only Studio: authoring and execution were separated; Orchestrator owns explicit launch.
  5. GoalState: expanding root transcripts became exact intent plus bounded outcome and recovery state.
  6. Pushed skills: optional role discovery became mandatory spawn-time role-skill injection plus on-demand pulls.
  7. Token-only accounting: duplicated credit semantics became one executable owner per dimension and provider-attributable usage.
  8. Thinner prompts: fixed scaffolding is tagged for expiry as frozen briefs and pushed skills shrink context.
  9. Catalog relocation: platform-neutral catalogs remain under .github/ until compatibility readers and migration ship.

Documentation archaeology

Stale residue is historical evidence, not active behavior: model-visible workers cannot summon whole pipelines, runtime supports bounded nesting, live economics is token-only, the extension host is retired, Pipeline Studio is builder-only, and executable budget resolution—not prompt prose—owns limits.

HI #4 retired: zero-cost routing became trivial in the single-host design. HI #6 retired: flat catalog layout is a code-organization rule rather than a safety property.

Quan hệ và bằng chứng

  1. CLI launches GoalState root controller.
  2. Console launches deterministic pipeline bằng --pipeline.
  3. GoalState routes sang worker loop; worker dispatches pipeline stages khi caller đã chọn pipeline.
  4. Worker loop calls LMRouter; LMRouter requests model provider.
  5. Worker calls Musubi MCP tools; MCP server delegates gates cho fail-closed policy và evaluator firewall.
  6. MCP server injects skills, loads memory, compresses context, persists state vào musubi.db và records audit vào audit.db.
  7. Top-level driver routes namespaced calls tới external MCP; đường này không qua Musubi gate/audit.
  8. Rust projection reads state và audit, projects sang React view model, rồi renders Console.
  1. CLI launches the GoalState root controller.
  2. Console launches an explicitly selected deterministic pipeline with --pipeline.
  3. GoalState routes work to the worker loop; selected pipelines dispatch sequential stages.
  4. The worker loop calls LMRouter, which requests the model provider.
  5. Workers call Musubi MCP tools; the server delegates to fail-closed policy and the evaluator firewall.
  6. The server injects skills, loads memory, fits context, persists state to musubi.db, and appends audit evidence to audit.db.
  7. The top-level driver routes namespaced external MCP calls outside the Musubi policy and audit boundary.
  8. Rust reads state and audit, projects a safe React view model, and Console renders it.
